# Deploying the backend: Render + Supabase (free plans)

The three websites run on Vercel ([deploy-vercel.md](deploy-vercel.md)). The FastAPI backend
(`apps/backend`) runs on **Render** as a Docker web service, and its PostgreSQL database is on
**Supabase**. The web app reaches the backend only through its `/api/v1/*` proxy (ADR-0001), so the
session cookie stays first-party on the Vercel domain.

```
browser ──► g-ai-app.vercel.app/api/v1/* ──(BACKEND_URL)──► g-ai-api.onrender.com ──► Supabase Postgres
```

Everything Render needs is in [`render.yaml`](../render.yaml) (a Render *Blueprint*). You only paste
one secret: the database connection string.

## 1. Supabase: create the database and copy the connection string

1. In <https://supabase.com/dashboard>, create a project (free plan). Pick the region closest to
   Render's Singapore region: **Southeast Asia (Singapore)**. Save the **database password** you set
   (you can reset it later under *Project Settings → Database*).
2. Open **Project Settings → Database → Connection string** (or the **Connect** button in the top
   bar) and choose the **URI** format.
3. Pick **Session pooler** (port **5432**, recommended). It looks like:

   ```
   postgresql://postgres.<project-ref>:[YOUR-PASSWORD]@aws-0-ap-southeast-1.pooler.supabase.com:5432/postgres
   ```

   - **Transaction pooler** (port **6543**) also works: the backend detects port 6543 and turns off
     asyncpg's prepared statements, which transaction pooling cannot keep. Force it either way with
     `DB_TRANSACTION_POOLER=true|false`.
   - Do **not** use **Direct connection** (`db.<project-ref>.supabase.co`): on the free plan it is
     IPv6-only, and Render cannot reach IPv6 addresses.
4. Replace `[YOUR-PASSWORD]` with the database password. If it contains characters such as
   `@ : / ? # % &`, URL-encode it first:
   `python -c "import urllib.parse; print(urllib.parse.quote('PASSWORD', safe=''))"`.
   A password of letters and digits avoids this.

   Paste that string **as is** into `DATABASE_URL` on Render. The backend accepts `postgres://…`,
   `postgresql://…` and `?sslmode=require` and converts them to its `postgresql+asyncpg://` driver.
   (Backends older than PR #8 need the prefix changed to `postgresql+asyncpg://` by hand; that form
   keeps working.)

   Keep this string secret: never commit it or paste it into an issue or chat.

You don't create tables in Supabase yourself. The backend container runs `alembic upgrade head` every
time it starts, which creates and updates the schema and loads the store catalog (products p1…p8).
To update the catalog later, run `python -m app.services.catalog --dry-run` (preview) and then without
`--dry-run`, from `apps/backend` with the same `DATABASE_URL` (or in the Render **Shell** tab).

## 2. Render: create the service from the Blueprint

1. In <https://dashboard.render.com>, click **New → Blueprint**.
2. Connect GitHub if asked and select the `mh4ns/G-AI` repository, branch `main`.
   Render reads `render.yaml` and shows one service, **g-ai-api** (Docker, Singapore, Free).
3. Render asks for the variables marked `sync: false`: paste the `DATABASE_URL` from step 1.4.
   The other variables are already set by the Blueprint:

   | Variable | Value |
   |---|---|
   | `ENVIRONMENT` | `production` |
   | `AUTO_CREATE_SCHEMA` | `false` (migrations run on start) |
   | `AUTH_COOKIE_SECURE` | `true` |
   | `BACKEND_CORS_ORIGINS` | `https://g-ai-app.vercel.app,https://g-ai-site.vercel.app` |
   | `SECRET_KEY` | generated by Render (random, kept across deploys) |
   | `TRUSTED_PROXY_HOPS` | `2` (Vercel rewrite + Render proxy), so login rate limiting sees the real client IP |
   | `DB_POOL_SIZE` / `DB_MAX_OVERFLOW` / `DB_POOL_RECYCLE_SECONDS` | `3` / `2` / `300`, sized for the free plans |
   | `DATABASE_URL` | the value you pasted |

   If your Vercel domains are different, change `BACKEND_CORS_ORIGINS` (comma-separated, no trailing
   slash) in the service's **Environment** tab.
4. Click **Apply**. The first build takes a few minutes. In the **Logs** tab you should see
   `Running upgrade -> ae6bddef5c1d, initial schema` and then `Uvicorn running on http://0.0.0.0:10000`.
5. Copy the service URL from the top of the page, e.g. `https://g-ai-api.onrender.com`, and check it:

   ```
   curl https://g-ai-api.onrender.com/healthz
   # {"status":"healthy","database":"connected"}
   ```

   `"database":"unavailable"` with status 503 means `DATABASE_URL` is wrong (prefix, password,
   or pooler host); fix it in **Environment** and Render redeploys.

After this, every push to `main` that changes `apps/backend/**` redeploys the service.

## 3. Vercel: point the websites at the backend

1. In Vercel, open **g-ai-app** → **Settings → Environment Variables** and add `BACKEND_URL` = the
   Render URL (`https://g-ai-api.onrender.com`, no trailing slash) for *Production* (and *Preview* if
   previews should log in too).
2. Do the same in **g-ai-site**: the store reaches the backend through the site's own `/api/v1`
   proxy.
3. `BACKEND_URL` is read **at build time** (Next.js rewrites), so redeploy both projects:
   **Deployments → … on the latest production deployment → Redeploy**.
4. Test: open `https://g-ai-app.vercel.app/login`, create an account, and check that **Today** shows
   `0 / … ml` water (server numbers) instead of the guest demo values, and that `+250ml` survives a
   reload.

If your Vercel domains are not `g-ai-app.vercel.app` / `g-ai-site.vercel.app`, update
`BACKEND_CORS_ORIGINS` on Render to match.

## Free-plan behaviour to expect

- **Render free** services sleep after ~15 minutes without traffic. The first request after that
  takes up to about a minute while the container starts (and runs migrations), so the first login
  of the day can be slow or time out once; retry.
- **Supabase free** projects are paused after a week without activity. Resume the project in the
  Supabase dashboard if `/healthz` reports `"database":"unavailable"` after a long break.
- Free Render instances have 512 MB RAM; the backend uses well under that.

## Running migrations by hand (optional)

The container already runs `alembic upgrade head` on every start. To run it yourself (e.g. to check
the connection string before deploying), from `apps/backend`:

```
pip install -r requirements.txt
DATABASE_URL='postgresql+asyncpg://…' python -m alembic upgrade head
DATABASE_URL='postgresql+asyncpg://…' python -m alembic current   # shows ae6bddef5c1d (head)
```

On Windows PowerShell, set the variable first: `$env:DATABASE_URL='postgresql+asyncpg://…'`.

## Troubleshooting

| Symptom | Cause / fix |
|---|---|
| Deploy fails: `SECRET_KEY must be set …` | `SECRET_KEY` missing or shorter than 32 chars. Blueprint generates it; if you created the service by hand, add one. |
| `prepared statement "__asyncpg_stmt_…" does not exist` | Transaction pooler on a port other than 6543 (or an older backend). Set `DB_TRANSACTION_POOLER=true`, or use the Session pooler (5432). |
| `OSError: [Errno 101] Network is unreachable` / timeout at start | You used the direct connection (IPv6). Use the Session pooler host. |
| `password authentication failed` | Wrong password, or special characters not URL-encoded. |
| `Can't load plugin: sqlalchemy.dialects:postgres` / `No module named 'psycopg2'` | Backend older than PR #8: change the prefix to `postgresql+asyncpg://`. |
| Login on Vercel says "Không kết nối được máy chủ" | `BACKEND_URL` not set on g-ai-app, or set without redeploying, or the Render service is asleep / failing `/healthz`. |
| Every login attempt is rate-limited together | `TRUSTED_PROXY_HOPS` is not `2`, so all users share the proxy's IP. |
